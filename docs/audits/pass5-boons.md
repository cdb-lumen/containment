# Pass 5: 24 additional boons (48 total)

Read-only audit of the current checkout. These are additions to the actual 24-entry catalog, not the older proposal in `docs/audits/boons.md`. No ranks, no new rarity tiers, no new families required. Every addition works with all five weapons; some explicitly reward a particular elemental build. Numbers are starting balance values in existing game world units.

## Shared mechanical contract

- A direct hit means the existing aggregate `(shotId,targetId)` hit; shotgun pellets never count separately. Rocket/grenade primary splash remains direct. Secondary damage never creates direct-hit events.
- A proc marked once per shot chooses the first eligible target in deterministic simulation order, not every pellet or splash victim. Per-target gates are keyed by target ID. Gates and counters reset each room.
- Every secondary damage instance uses the original chain ID and incremented depth. Max depth 3, 32 events per chain, 6 area targets. Delayed effects preserve provenance; they do not restart a fresh chain.
- All nearby target selection is living targets within radius AND `canAffect(center,target)`, nearest distance then numeric ID. Exclude the source when text says “other.” Friendly fields never damage the player.
- Amounts below are flat secondary damage unless otherwise stated. No multiplying secondary damage by projectile stats. No percent-max-health damage or unconditional boss executions.
- A status stores expiry, next tick and provenance; refreshing it preserves next tick and does not stack damage. Reactions resolve from pre-hit status state, then consume statuses, then apply new ones. One reaction per shot/target. This prevents a hit from creating both ingredients and detonating them immediately.

## Important existing bugs / integration risks

1. **Build and checkpoint still hard-cap 24.** `builds.ts:isValidBuildState` and `checkpoints.ts` both use 24. Replace with `MUTATION_IDS.length` (48), extend `types.ts:MutationId`, and test an owned 48-ID state. `addMutation` currently validates input but can append a 25th item that immediately becomes invalid. Existing valid checkpoints remain structurally compatible; extending ID whitelist alone does not require changing shape/version.
2. **Runtime procs bypass the reducer's rejection and event budgets.** `MutationRuntime.hit()` dispatches the hit, then unconditional runtime counters/Pressure Point/Arc/Incendiary continue even if `resolveMutationEvent` rejected it. `#damage` itself has no cause/depth validation. Put new runtime commands behind one accepted-event/proc budget or move counters/proc commands into reducer. Never make 24 more independent unbounded branches.
3. **Primary-hit counters are per shot/target, not once per shot.** Current Pressure Point and Arc increment for every different target reached by one shotgun/plasma/rocket shot. Existing card “pellets count as a single hit” is true only for the same target. Decide intentionally: preserve aggregate shot/target damage effects, but use a separate `seenProcShots` for explicit once-per-shot mechanics.
4. **Final boss death can commit the room too early.** `DepthGame.damage()` synchronously handles queen-defeated -> director -> clearRoom/save before caller invokes `mutations.hit/kill`, so final-kill recovery is absent from saved resources and delayed effects can run against a transitioned room. Defer room clear until the current combat transaction and queued mutation commands complete. Re-check `status==='playing'` inside pending secondary execution/update loops.
5. **Stale snapshot burn loop.** Burn update keeps an earlier target snapshot for several catch-up ticks; death removes burn but the local loop can still call #damage again. Host rejects it, but a larger status system would waste events/VFX and could trigger wrappers. Break on kill, refresh active lookup, and guarantee exact bounded ticks. Current cap 4 then deleting an expired burn can discard damage after a large delta; current DepthGame 50 ms cap masks this.
6. **Slow expiry currently restores 1 unconditionally.** Root/field/chill need a single `effectiveSlow(id)` compositor. Otherwise expiring frost patch or root can wipe a still-active chill. Use min multipliers, root=0 for movable targets, one setSlow call on change. Queen currently receives no actual slow because host ignores negative IDs; avoid claiming partial Queen slowdown.
7. **Cold Snap overwrites existing stacks.** completedReload always sets 2, so a reload lowers a 3-stack chill to 2. Merge with max(stacks,2) and max expiry if retaining current card wording. Frost Armor checks map membership rather than live expiry; use `expiresAt>time` for all status death rewards.
8. **Lethal shot hit ordering matters.** `hit()` happens after base damage. Live-only status application cannot mark an enemy killed by that same hit; Flame/Toxic death effects should require an already-active status, clearly specified above. First Impact/Executioner require maxHealth/pre-hit snapshot, but must not resurrect or redundantly damage killed entities.
9. **State must be bounded and reset.** New target maps contain max active/recent encounter entities, first-hit dedupe <=2048, pending detonations <=6, fields <=4. Restore/room entry reset timers, charges, heal caps and projected VFX. Delayed explosions use saved point centers rather than dead target lookup.
10. **Selection eligibility uses only all-of prerequisites.** Existing `requires` supports all IDs, ideal for the two dual-element boons above. Avoid introducing OR/family gates for this pass. The “general” opening filter excludes a hard-coded weapon-only list; every new addition is universal so no new exclusions needed. With 48 cards, keep at least one immediately useful card and do not oversample two-source reaction cards before their sources exist.

## Recommended implementation layout

- Put exact tunable numbers in catalog config or an adjacent typed effect constants object; avoid prose drifting from implementation. Keep four existing families and common/rare UI.
- Extend `MutationTarget` with `maxHealth`; host with `player()` for Concussion/area reactions, and a semantic `boonEffect` kind union including `poison`, `shatter`, `nova`, `charge` if useful. Source coordinates currently exist, so reuse current effect payload.
- Runtime owns statuses, pending detonations, bounded fields, per-target cooldowns, first-hit/last-weapon maps and per-shot gates. Factor helpers `alive`, `selectNearby`, `applyStatus`, `damageSecondary`, `explode`, `queueDetonation`, `effectiveSlow`; centralize terminal kill/recovery once.
- `CombatSystem.fire` exposes whether the shot consumed Hot Reload, in a projectile field shared by all pellets; runtime `hit/kill` receives it. For Blood Capacitor, a combat heal signal provides actual delta. Completed reload already has a DepthGame hook, but pass weapon/rounds transferred explicitly.
- `DepthGame.hurt` captures before/after resources once and invokes runtime hurt only for applied damage on a living player. No new per-frame polling for armor-break conditions. `CombatSystem.addGrenades` already exists for Salvage.
- Preserve enemy armor and boss invulnerability in the authoritative damage host. Elemental damage should be recognizable effects and status rules, not duplicate enemy-health mutations.

## Mobile-safe VFX

Keep existing pools: glow360, smoke80, debris80, pulses24, decals64, beams320. No point light per proc and no mesh per status. At most 6 admitted boon bursts/frame, 2 arc connectors/frame, 4 visible fields, 6 pending charge markers, 32 enemy status markers. Render gameplay even when a cosmetic burst is dropped. Use existing pooled beam geometry for ricochets/lances; narrow rings and 3-8 motes for elemental reactions. Route new friendly blasts through boon pulses rather than the full grenade/explosion recipe (26 glow + smoke). Reserve enemy warning visibility above friendly fields. Low quality halves particles but retains charge markers, fields and main lightning path. Reuse current affliction tint capability with poison added if practical; do not clone materials every tick.

## Focused verification for parent implementation

- Catalog count=48, IDs unique, all descriptions have live effect behavior, strict invalid ID rejection, old checkpoints accepted, 48-owned validator accepted.
- Fake-host runtime: shotgun multi-pellet and rocket multi-victim once-per-shot gates; poison exact 30 damage without refresh stacking; reactions require preexisting ingredients, consume correct status, preserve cause; secondary procs can't recursively hit.
- Cold/root/field composition and expiry; cover blocks arc/area/status spread; immovable Queen never roots or launches; charges detonate after source death at saved point.
- Actual hurt/reload/heal hooks: no barrier or armor-break trigger after lethal hurt; no Blood Price retaliation; full-health heal doesn't charge capacitor; completion caps and grenade capacity honored.
- Final-kill transaction saves post-proc resources and ends with no active stale effects; reset clears counters/fields/maps.
